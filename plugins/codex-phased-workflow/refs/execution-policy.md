# Execution economics and quality

Shared Claude/Codex policy. Adapters change capabilities, never acceptance or authority.
Record rationale in existing Notes/notes.md; no new portable fields are required.

## Choose the delivery shape before mode and channel

Bound reconnaissance to the facts needed to choose. Compare design, implementation,
context reloads, coordination, verification and likely correction; do not invent savings.

| Shape | Choose when |
|---|---|
| One engineer task | One coherent result fits context with diagnosis/verification reserve; no useful intermediate gate. Hard coupled bugs can fit. No workflow interview or `.phased/` needed. |
| One durable phase | The same coherent result needs unattended execution, restart evidence or handoff. Quality-check is not another implementation phase. |
| Several phases | An intermediate result changes the next decision, context cannot fit safely, or independently testable deliveries justify handoff. Each seam names evidence and consumer. |
| Macro-phases | A usable capability, compatible migration or accepted interface informs later planning. Detail only the next ready macro; retain later entry/exit, dependencies and open decisions. |

Files and phase counts are warnings, not cutoffs. Keep tests with implementation.
Use batches for broad coherent edits. Merge boundaries that only cause rereading.

## Assign responsibilities, not obligatory sessions

| Role | Owns | Dispatch when |
|---|---|---|
| Engineer | Design, contracts, diagnosis and difficult implementation | Unknown premise, coupled behavior or costly reversal |
| Worker | Decided bounded change, pattern and measurable acceptance | Tests distinguish success; no design decision delegated |
| Foreman | Ownership, sequencing, budget, evidence and escalation | Tools handle routine state; sessions handle real decisions |
| Reviewer | Independent behavior, contract and integration checks | Non-trivial implementation; depth follows risk |

A compact job's engineer may finish it; four roles do not require four sessions.
Use tools for exact transformations. Low effort retains the full contract.
Codex maps opus (and legacy sonnet) to gpt-5.6-sol and fable to gpt-6-astra; Claude retains opus/fable. Choose Astra/fable upfront for architecture, coupled diagnosis, difficult implementation or material replanning, including one engineer alone. Sol/opus handles decided work and routine review; specialist review or repair may use Astra/fable for a concrete unresolved risk.
Compare one Astra engineer with Sol plus handoffs before dispatch, not only after failures. Record the reason, preserve independent review and the attempt budget, and report unavailable models rather than silently substituting. Savings require measurement.
Low/medium effort suits decided work, high suits unknowns; higher effort needs evidence.

## Correction, review and budget

Allow one diagnosed local correction; the same failure twice or a missing premise
ends guessing. Record evidence; one fresh engineering repair may follow. Failed repair
stops. Relaunching or changing model does not reset attempts.
Quality-check collects QA, naming and review findings at one revision, deduplicates
root causes, then applies one approved batch. One independent verification covers the
delta and affected consumers; new scope needs review. Residual defects prevent a clean
verdict. No automatic corrective phases or repeated whole-diff hunts on unchanged scope.
Panel starts with one reviewer and adds at most one distinct-risk specialist. Evidence,
not votes, resolves disagreement. PR review reuses coverage and checks delivery/delta.
Keep implementation, review and repair allowances separate. A soft boundary reassesses
progress; a hard boundary prevents new attempts and preserves a checkpoint. Consult
holds retain human authority. Claim enforcement only for supported launcher controls.
Record model, effort, attempt, outcome and available usage outside the portable contract.
Unknown usage is unavailable, not zero; subscription usage is not a dollar invoice.
Paid calibration requires an explicit experiment budget.
